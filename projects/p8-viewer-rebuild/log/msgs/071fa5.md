## ④ 時系列の図に要りそうで無いもの・あやしいもの
1. **assign/launch/teardown の中身が event に無い。** `to` が "-"、対象メンバーは summary の文字列（"p1-org-status/pm" 等）に入るだけで、position/occupation/model/session id/teardown の report パスは kv に入っているのに snapshot に出ていない。入れ替え・メンバーの帯の始まりと終わりを機械で引けない。
2. **入れ替えたメンバーの前後がつながらない（p1 の PM）。** assign が 2 回（n=2 と n=7、teardown n=6 を挟む）あるのに、tree の members は 1 件（pm）で session は後の方だけ。セッション報告のファイルがメンバー id 単位なので 1 回目の PM の報告は上書きされ、performance.sessions（全 43 件）にも 1 回目は出ない。「1 回目の PM が何時〜何時」を出せる項目が無い。`reassign` の event は p1〜p8 に 1 件も無く（counts.reassign は全部 0）、入れ替えは assign の 2 回目としてしか読めない。
3. **メンバー個人の帯の区間が無い。** member に launched_at/closed_at は session 経由でしか無く、報告の無いメンバー（進行中の p8 など）は区間が取れない。
4. **メンバーの並び・ペルソナ。** members は component.json の辞書順で、役割（leader → worker → reviewer）の並びを表す項目が無い。ペルソナ（assign の --persona）は member.json にも event にも出ていない。occupation は p1〜p7 で全部 null（p8 の assign には入る見込み）。
5. **入れ子の event の帰属。** event.component は from（user のときは to）から決まるので、PM→リーダーの assign はプロジェクト側、リーダー→作業者はチーム側と読めるが、`to` が "-" の event（assign・launch）の宛先チームは summary からしか分からない。p6 の 2 チーム（uiux-research 19 件・org-build 37 件）は tree の children で別々に読める。コーディネーター 2 人（coordinator-uiux-research・coordinator-org-build）も members に出る。
6. **線の向き。** from/to は member id そのままで、tree の members.id と突き合わせれば引ける。ただし to が "user" や "-" のものは線にならない（user を帯として持つ項目が無い）。
7. **往復のつながり。** review_ng → rework、相談 → 返し → 合意 を結ぶ項目（返信先・同じ依頼の連なり）が無い。時刻順に並べて推測するしかない。
8. **開いているプロジェクト**: p8 は closed_at が null で、duration_min は generated_at までの時間。メンバーの state は member_state で出る。
