## 試走で分かったこと（連絡・決まり）

1. **`wait --cc` が作業者 → レビュアーの review_request を拾わなかった。** リーダーは 9 分の時間切れで戻り、レビュアーの起動が約 10 分遅れた。PM の `watch` で「reviewer 未起動・review_request 止まり」に気づき、リーダーへ知らせて動いた。
2. **「レビュアーは最初の review_request の後に起こす」の決まりだと、作業者は知らせる相手のタブが無い。** 1 と重なると止まる。レビュアーを最初から起こすか、作業者の review_request をリーダーにも cc で知らせる（Orca の知らせを出す）形が要りそう。
3. **`orca terminal send` が毎回「Enter が飲まれたかもしれない」と警告する**が、相手は受け取っていた（notify_recv で確認）。PM は 1 回目だけ `--retry-request` で再送を試したが、同じ警告が出た。警告を信じて再送すべきかの決まりが無い。
4. **`inbox --via notify --ref <hash>` は、その件が `wait`（poll）で先に読まれていると「新しいものは無い」になる、または後から来た別の件を読む。** PM の側でも、9997e5 は「新しいものは無い」、d9ba25 の知らせで読んだのは次の done（950902）だった。知らせで届いた記録が残らず、notify-stats の「届かなかった」に数えられる（今回の 2 件は、最初の PM の start 3a1eb3〈入れ替え前のタブ宛て〉と、リーダーの done 950902）。
5. **最初の PM は 11 分で入れ替えになった**（自己申告なし、charter.md だけ変えていた）。入れ替え後の PM には、前の PM の状況の引き継ぎが来なかった（start は前の PM 宛ての 3a1eb3 だけで、inbox で読めた）。
6. 見本の id は根っこの親ディレクトリ基準（`rel_id`）で、見本のディレクトリ名と揃える必要があるが、決まりに書かれていない（作業者の申告）。
