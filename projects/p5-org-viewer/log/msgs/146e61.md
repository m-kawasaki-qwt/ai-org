## 完了条件ごと

1. **export とスキーマ** — 満たす。`orgctl export --projects <ai-org>/projects --out <file> --check`。`NOISE_KINDS`・`read_events`・`member_state` などをそのまま呼び、自前の集合は `LIFECYCLE_KINDS`（帯に畳む種類。スキーマで定義）だけ。追加の import は標準ライブラリのみ。既存の関数の変更なし（+409 行・削除 0）。読むだけ（閉じたプロジェクトの記録が変わらないことを確認）。リーダーも打ち直して `--check` 通過を確かめた: 5 プロジェクト・受け箱 8・未読 1・監査の改訂案 5・unclear 56・セッション報告 22。トークンは記録を awk で足した値と一致（作業者・レビュアーが突き合わせ）。
   - スキーマの説明: `teams/viewer/schema.md`（決めごと 3 点はここの「決めたこと」）。JSON Schema: dev-tools worktree `org/schema/snapshot.schema.json`。
2. **ビューア** — 満たす。`snapshot.json` だけを読む（src に記録の読み込みなし）。5 画面とも冒頭は数字・状態・一言、詳細は `<details>`。
   - 一覧: 開いている・未読・判断待ち・トークンのカード。行の「いま／最後」は、閉じたものは user 宛ての結果の report、開いているものは最後のやりとり。
   - プロジェクトの中: 木とメンバーの状態、時系列（節目は帯、プロジェクトの層の行だけ並べ、チームごとに畳む。本文なしの done は件数だけ）、往復・作り直し。
   - 受け箱: 中身のある report と未読を先に。既読の本文なし完了通知は畳む。
   - パフォーマンス: プロジェクトごと・立場ごと・セッションごと。報告の無い分は「一部のみ」。
   - 監査・unclear: p3 の改訂案 5 件（題と対象のファイル、本文は畳む）、unclear 56 件はプロジェクト別・立場別の件数から開く。
3. **実物で表示・build・スクリーンショット** — 満たす。リーダーが `npm run build` を打ち直して 9 ページを確認。スクリーンショット（`projects/p5-org-viewer/teams/viewer/screenshots/`）:

## 申し送り

- **dev-tools 本体へ入れるまで、README の `<dev-tools>` の orgctl に `export` は無い。** worktree をマージしてから使える。
- `npm install` は、`~/.npm` のキャッシュの権限が壊れている環境では失敗する（作業者は `--cache` を TMPDIR に向けて回避）。README には書いていない。
- `astro preview`・Playwright はサンドボックスの外で動かした（localhost の待ち受け）。
- 時系列は、プロジェクトが長くなるとプロジェクトの層の行も増える。絞り込みは今は無い。
- ai-org の `tools/org_status.py`・`org_timeline.py` は触っていない（PM の指定）。
