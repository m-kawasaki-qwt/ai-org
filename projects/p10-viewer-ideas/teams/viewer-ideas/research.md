# 外のリサーチ: ビューアに持ち込める考え方

## Summary

- 道具を並べず、考え方 11 件に絞った。出典 URL はすべて 2026-10-24 に開き、書いた内容がそのページにあることを確かめた（確かめきれなかった点は各件に「未確認」と書いた）。
- この組織にいちばん効くのは次の 4 つ。
  1. **受け箱で選ぶだけ**（件 2）… 判断待ちを「承認・却下・重複・先送り」の 1 操作にする。叩き台 7 と、川崎さんの「選ぶだけ」に直結。
  2. **役割を名前で見せる**（件 3）… 「いま誰が何を持っているか」を役割名で出す。叩き台 3。

  4. **実行ごとの 1 枚要約**（件 7）… 完了条件の通否を 1 枚に。叩き台 5・4。
- 外の道具は「全部見せる」寄り。持ち込むときは、各件の注意のとおり削ること。
- 叩き台に無い新しい案は 3 件（件 4・5・9）。件 10 は叩き台 3 の拡張。

## 各件

### 件 1 未読だけを先に

- **見せ方**: GitHub の通知の受信箱は、「完了（Done）」にしていない通知だけを出し、未読だけの絞り込み、後で見るための「保存（Saved）」を持つ。Linear の Inbox も既読／未読の切り替えと先送り（snooze）を持つ。「前に見た時点」を基準に、新しいものだけが残る。
- **出典**: https://docs.github.com/en/subscriptions-and-notifications/how-tos/viewing-and-triaging-notifications/managing-notifications-from-your-inbox ／ https://linear.app/docs/inbox
- **叩き台**: 1（前回から何が変わったか）
- **注意**: 通知は 1 件ずつ既読にさせる作り。持ち込むのは「前回開いた時刻より新しい変化の件数」だけにし、1 件ずつの既読操作は持ち込まない。

### 件 2 受け箱で選ぶだけ

- **見せ方**: Linear の Triage は、他チームや連携から来た項目の受け箱。1 件開いて、承認（1）・却下（2）・重複（3）・先送り（H）のどれかを押す。承認すると、その場でコメントを残してバックログへ移る。判断が「選ぶ 1 操作」になっている。
- **出典**: https://linear.app/docs/triage
- **叩き台**: 7（直し待ち。「重複」の考え方が、同じ問題をまとめる操作に当たる）。判断待ちの画面にも効く。
- **注意**: ビューアは実装しない（読むだけ）ので、「ボタンを押して反映」は持ち込まない。選択肢と推奨を並べ、押す操作は書かない。

### 件 3 役割を名前で見せる

- **見せ方**: incident.io は「インシデントリード」「コミュニケーションリード」などの役割に人を割り当て、いまだれがどの役割かをインシデントの画面に出す。役割は組織ごとに作れる。
- **出典**: https://docs.incident.io/incidents/roles
- **叩き台**: 3（いま誰が誰を待っているか）
- **注意**: 割り当て・権限制限の機能は要らない。「いま持っている」「待っている相手」の 2 つだけを役割名で出す。

### 件 4 経緯を 1 行報告から自動生成

- **見せ方**: incident.io は、状態の変更や重大度の変更、ピン留めされたメッセージから、インシデントのタイムラインを自動で作る。後から手で足したり直したりできる。経緯は人が書くのではなく、起きた記録から組み立てる。
- **出典**: https://docs.incident.io/post-incident/timeline
- **叩き台**: 新しい案（プロジェクトの画面の頭に、「何があって、いまどこか」を 1 行報告から作った数行で置く）
- **注意**: 手で直す機能は要らない。1 行報告（種類と宛先）から機械的に作る数行だけにして、全部は並べない。

### 件 5 筋と詳細を別の層に

- **見せ方**: LangSmith の Trajectory は、メイン・サブのエージェントの会話とツール呼び出しを、入れ子のノイズを除いて時系列に 1 本にした層。Turns は 1 ターンずつのカードで、開閉できる。細かい入出力・時間・エラーは Details の層に分ける。同じ実行を 3 つの層で見せ、既定は要点の層。Langfuse も、時系列図とツリーを切り替えられる。
- **出典**: https://www.langchain.com/blog/langsmith-trajectories-tracing ／ https://docs.langchain.com/langsmith/view-traces ／ https://langfuse.com/changelog/2025-03-19-new-trace-view
- **叩き台**: 叩き台に無い（画面全体の構造）。3 にも効く。
- **注意**: 層を 3 つに増やすと、川崎さんの「何のための列か」に当たる。いまのビューアの「図 → パネル」を 2 層のまま保ち、要点の層に何を置くかだけを見直す。

### 件 6 外れ値を先に出す

- **見せ方**: Honeycomb の BubbleUp は、ヒートマップで目立つ領域を選ぶと、選んだ部分と残りを項目ごとに比べ、何がその部分を特徴づけているかを並べる。Honeycomb Intelligence を有効にすると、違いの要点が平易な文で上に出る。「平均」でなく「普通と違うもの」から見せる。
- **出典**: https://docs.honeycomb.io/investigate/analyze/identify-outliers
- **叩き台**: 7、8（異常に長いもの・差し戻しが多いものを先に）
- **注意**: 統計の機能は要らない。「p1 からの線で外れたプロジェクト」を強調するだけでよい。

### 件 7 実行ごとの 1 枚要約

- **見せ方**: GitHub Actions は、ワークフロー実行の画面に Markdown で書いたジョブの要約を出せる。実行の結果の要点が、ログを開く前に 1 枚で見える。
- **出典**: https://github.blog/news-insights/product-news/supercharging-github-actions-with-job-summaries/
- **叩き台**: 5（完了条件の通否）、4（成果物へのつなぎ）
- **注意**: 要約は書き手が作る前提。この組織では、完了条件の通否と根拠のリンクを、記録から機械的に出す形にする（手で書かせない）。

### 件 8 前の期間との変化率

- **見せ方**: Sleuth の Trends ダッシュボードは、期間を選んで DORA 指標の推移を出し、期間ごとの変化率（パーセント）と、増えた原因へのドリルダウンを持つ。CircleCI の Insights も、成功率・実行時間の時系列と集計を出す。
- **出典**: https://help.sleuth.io/sleuth-dora/modeling-your-deployments/organization/trends ／ https://circleci.com/docs/guides/insights/insights/
- **叩き台**: 8（プロジェクトをまたいだ推移）、1
- **注意**: 指標を増やさない。時間・トークン・差し戻し・人の介入の 4 本まで。プロジェクトが少ない間は変化率より、点を並べるだけにする。

### 件 9 遅いところを強調する

- **見せ方**: Jaeger のトレース画面は、設定で有効にすると、各スパンのクリティカルパス（全体の時間を決めている区間）を強調して表示する。Langfuse のタイムライン図は、遅い箇所・並列・多段の流れを見つけるための図。
- **出典**: https://www.jaegertracing.io/docs/2.22/deployment/frontend-ui/ ／ https://langfuse.com/changelog/2024-06-12-timeline-view
- **叩き台**: 新しい案（プロジェクトの図で、全体を決めている待ちの区間だけ濃くする）
- **注意**: Jaeger の細かい表示の中身はページに設定の説明しか無く、見え方は未確認。持ち込むのは「いちばん長い待ち 1 本を濃く」だけ。

### 件 10 実行の筋を図で

- **見せ方**: Arize の Agent Graph / Path は、エージェントの実行経路を対話的なグラフと経路図で出す。OpenAI の Agents SDK は、LLM 生成・ツール呼び出し・ハンドオフ・ガードレールの記録を Traces ダッシュボードで見せる。エージェント間の委譲（ハンドオフ）が一級の項目になっている。
- **出典**: https://arize.com/docs/ax/observe/tracing/agents ／ https://openai.github.io/openai-agents-python/tracing/
- **叩き台**: 3、新しい案（往復の矢印に「待ち」と「ハンドオフ」の別を付ける）
- **注意**: いまのビューアは p8 で入れ子の帯とやりとりの線を持つ。足すのは、線の種類の区別だけにする（図を作り直さない）。

### 件 11 手が入った回を印で数える

- **見せ方**: エージェントの観測道具は、人の入力と AI の出力を別の種類として記録する（LangSmith の Trajectory は、人・AI・ツール・サブエージェントのメッセージを順に並べる）。種類が分かれているので、人の回数は数えるだけで出る。
- **出典**: https://www.langchain.com/blog/langsmith-trajectories-tracing
- **叩き台**: 6（人が手を入れた回数）
- **注意**: 記録の側で、根っこ・川崎さんの発言を種類として区別できるかが前提。区別できないなら、画面の前にデータの足しが要る（未確認。叩き台の評価で確かめる）。
