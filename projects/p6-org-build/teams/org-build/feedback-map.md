## 防げない・弱いもの

- **7 YAML の写し（一部）:** 「元のデータの構造の写しか」は画面だけでは決まらない。design.md の B-02・B-05 で作る前に止め、画面では症状（C-12・C-06）で拾う。design.md に書いた理由が苦しい言い訳でも、レビュアーが B に照らして見抜けるかに掛かる。
- **10 前の HTML との比較（一部）:** 前の版より良いかは項目にしていない（一般のセオリーに無い）。良かった中身（帯と線で関係が見える）は C-10 で問える。
- **15 の後半・24 監査のまとめ方（防げない）:** データの構造と、まとめを作る仕組みの設計。UI の判定の基準の外。別の作業として要る。
- **16 触り心地（引っかからない）:** 感想の言葉のままは判定にしない。分けた項目（押せる手がかり・要点・崩れ）で拾う。
- **共通の弱さ:** どの段の判定も、その人が自分で撮って当てることに掛かっている。撮らずに承認したら止まらない（規範で「自分で撮る」「本文に画像のパスと判定を書く」を必須にして、記録から監査役が追えるようにした）。
