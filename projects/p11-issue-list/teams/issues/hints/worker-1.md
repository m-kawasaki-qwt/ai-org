# ヒント（worker-1）

- 抜き出しはスクリプトで先に機械的に済ませる（yaml の `unclear`・`not_done`、msgs の「うまくいかなかったこと」節、events.log で引ける review_ng・rework・blocked・escalate の本文、監査 2 種、job の README の該当節）。出力は 1 行 1 件、参照元（ファイルと行、または hash）つき。ファイルごとの件数表を必ず付け、0 件ならその理由を書く。
- 抜き出した段階で、いったんレビュアーに網羅だけを見てもらう（1 回目の review_request）。まとめに入るのは承認のあと。
- まとめで一番崩れやすいのは「原文の直し方・『〜すべき』が混ざること」。抜くのは誰が・何をして・どうなったか、だけ。
- 同じ問題の寄せ方は、言い方でなく中身で判断する。寄せた根拠と入れなかった理由は対応表に残す。
- 「直った」は、main にマージ済みの記録とその後の再発なしが両方揃うときだけ。迷ったら「不明」。
- 数と並べ替えはすべてスクリプトで。作り方（読んだ場所・まとめ方の基準・並びに使った回数）を issues.md 末尾に書く。
